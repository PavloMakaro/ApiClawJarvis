API Документация для Jarvis (Агент)
=====================================

Агент предоставляет HTTP-интерфейс, который может работать одновременно с Telegram ботом.
По умолчанию API доступен по адресу: `http://localhost:8080/`

---

## 1. Отправка сообщений и файлов (Чат)
**Endpoint:** `POST /chat`

Позволяет отправлять текстовые сообщения, а также загружать файлы, изображения или голосовые сообщения. Возвращает ответ в формате Server-Sent Events (SSE) в реальном времени.

### Параметры запроса (application/json)
Если вы отправляете только текст, можно использовать простой JSON:
- `chat_id` (обязательно, строка): Идентификатор пользователя или чата.
- `message` (обязательно, строка): Текст сообщения пользователя.

*Пример (cURL):*
```bash
curl -X POST http://localhost:8080/chat \
     -H "Content-Type: application/json" \
     -d '{"chat_id": "user123", "message": "Привет! Как дела?"}'
```

### Параметры запроса (multipart/form-data)
Если вам нужно отправить файл (картинку, документ, голосовое), используйте формат формы `multipart/form-data`:
- `chat_id` (обязательно, строка): Идентификатор пользователя.
- `message` / `caption` (опционально, строка): Подпись к файлу или текст.
- `file` (обязательно, файл): Отправляемый файл.

*Пример загрузки файла (cURL):*
```bash
# Отправка картинки с подписью
curl -X POST http://localhost:8080/chat \
     -F "chat_id=user123" \
     -F "caption=Что на этой картинке?" \
     -F "file=@/path/to/image.jpg"

# Отправка голосового сообщения
curl -X POST http://localhost:8080/chat \
     -F "chat_id=user123" \
     -F "file=@/path/to/voice.ogg"
```

### Формат ответа (SSE Stream)
Ответ приходит в виде потока (Server-Sent Events) со строками `data: {JSON}\n\n`.
Возможные статусы:
- `started`: Начало обработки.
- `thinking`: Агент размышляет (внутренние шаги/планирование).
- `plan_ready`: Сгенерирован план выполнения задачи.
- `plan_step_start`: Агент начал выполнение шага из плана.
- `thinking_stream`: Поток "мыслей" агента.
- `tool_use`: Использование инструмента (поиск, исполнение кода и тд).
- `observation`: Результат работы инструмента.
- `final_stream`: Поток финального ответа агента частями (для стриминга UI).
- `final`: Полный и окончательный ответ.
- `stopped`: Обработка принудительно остановлена.
- `error`: Произошла ошибка.

## 2. Остановка выполнения
**Endpoint:** `POST /stop`

Прерывает выполнение текущей генерации и вызов инструментов для пользователя.

### Параметры запроса (application/json)
- `chat_id` (обязательно, строка): Идентификатор пользователя.

*Пример (cURL):*
```bash
curl -X POST http://localhost:8080/stop \
     -H "Content-Type: application/json" \
     -d '{"chat_id": "user123"}'
```

*Возможный ответ:*
```json
{
  "status": "success",
  "message": "Остановлено."
}
```

## 3. Очистка контекста/памяти сессии
**Endpoint:** `POST /clear`

Очищает всю историю переписки и контекст для данного пользователя, начиная всё "с чистого листа".

### Параметры запроса (application/json)
- `chat_id` (обязательно, строка): Идентификатор пользователя.

*Пример (cURL):*
```bash
curl -X POST http://localhost:8080/clear \
     -H "Content-Type: application/json" \
     -d '{"chat_id": "user123"}'
```

*Возможный ответ:*
```json
{
  "status": "success",
  "message": "Память очищена, сэр."
}
```
